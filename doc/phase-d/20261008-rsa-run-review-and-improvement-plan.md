## 1. 结论与证据范围

该次运行耗时约 463.9 秒、2 个模型回合、31 次工具调用，最终为 `format_only`，`verified=false`。它没有解出正确答案，也没有证明附件无解。

直接错误是模型混淆了 RSA 指数字符串与成功提示字符串；设计上的问题是摘要遗漏关键数据、缺少事实核验、复现未绑定原始数据，以及终止策略推动了后续猜测性提交。

本次只读检查了日志、已保存脚本、工具输出和原附件字节，并完成 ELF 地址映射与候选的整数运算检查；没有启动附件、调用模型、修改原运行记录。日志引用的 118 个不同 artifact 的长度与 SHA-256 均匹配；附件 hash 与运行元数据匹配。该检查证明所读内容与记录一致，不等于日志有数字签名或解题推论正确。

### 1.1 已确认的事实

| 事件/位置 | 观察 | 结论边界 |
| --- | --- | --- |
| seq 10–26 | 启发式分类已提示 reverse/pwn，但模型选择 crypto，并尝试把 ELF 当 UTF-8/JSON 读取 | 类型信息未形成有效的操作前置条件；不说明跨类别分析应被禁止 |
| seq 37、47、91 | 字符串摘要只列长度至少 6 的内容，没有地址 | 五字符的 RSA 指数未显示；摘要不是完整字符串清单 |
| seq 51 与附件地址 | 反汇编在 `0xcc7` 处读取十进制指数，成功分支引用 `0xccd` | 原附件分别是 `65537` 和成功提示，模型把两者混淆 |
| seq 81 与附件地址 | 模型称 scanf 使用不受限的 `%s`，原附件 `0xc26` 实际为 `%99s` | 又一项未读取原始字节便下结论的事实错误；不能据此认定存在栈溢出 |
| seq 64 | `integer_nthroot` 从错误的 SymPy 模块导入失败 | API 使用错误，不能归为“环境未安装 SymPy” |
| seq 72、80 | 有限范围的分解探测没有找到因子 | 只说明这些尝试失败，不能说明 RSA 不可解 |
| seq 92–99 | 复现脚本硬编码错误的指数文本，得到解析失败和指数为零 | 验证了模型构造的假设，未验证原附件的实际参数 |
| seq 119–123 | 第一轮宣称无解后，主控继续要求使用工具；第二轮提交了提示字符串包装出的候选 | 终止策略没有区分“明确未解出”与“仍应继续求解” |
| seq 124、127 | 候选只获 `format_only`，运行立即结束 | 格式校验正确标记了未验证，但结果接纳策略没有要求推导或检查依据 |

第二轮 prompt 的 hash 与当前循环中的固定继续提示完全一致，可以确认继续提示的内容。无法由此判断模型内部动机。

### 1.2 不应据此认定的问题

- 没有 oracle 是真实 CTF 的正常情形，不应强制用户提供已知答案。
- 现有 `format_only` / `verified=false` 标记没有把格式匹配冒充验证成功；缺陷在候选接纳与终止策略，不是该标记本身。
- 该次记录没有表明缺少必要工具。GMP、Python、GDB 等已可用；没有执行题目输入验证是策略未使用能力，不能直接归因于环境不支持交互。
- 反汇编回复有截断标记，但关键调用位置已出现在返回内容中。截断是需改进的展示因素，不能当作本次误读的已证实根因。
- 单次失败不能用于估算模型总体能力、解题成功率，也不能证明升级模型一定有效。

## 2. 缺陷归属：通用机制与题型实现分开

此前按单次案例组织的 F01–F09 保留编号用于追溯；实施细节以新拆分的两份计划为准，原混合 R1–R3 路线由下表的新路线替代。

“通用问题”表示机制适用于不同题型，不表示已证明其他真实题目都发生了同样错误。把一个案例推广为成功率结论需要跨题型评测。

| 原编号 | 本次暴露的问题 | 通用层职责 | 题型层职责 | 新任务映射 |
| --- | --- | --- | --- | --- |
| F01 | 摘要漏短字符串且无地址 | 摘要覆盖/截断说明、来源引用与有界补充观察 | 二进制字符串偏移、ELF 地址映射、原始字节读取；普通文件偏移能力可共享 | G02；V01 |
| F02 | 关键假设未查证就升级成结论 | 事实/假设/实验区分、强结论边界和矛盾复核约定 | Reverse 核实参数地址、调用约定、格式串及分支；其他题型定义自己的事实检查 | G03；V02 |
| F03 | 硬编码实验自证错误假设 | 实验来源与输入版本绑定，区分假设实验与原题复现 | Reverse 从附件取参数并检查原程序；Crypto 记录参数表示及运算假设 | G03；V02/V03，Crypto 按需接入 |
| F04 | 明确未解出后仍要求继续求候选 | 结构化完成、未解出终态、继续策略与生命周期 | 领域工作流提供未完成项和可选下一步，不控制通用终止 | G01 |
| F05 | 候选、格式检查与结束耦合 | 记录/检查/完成分离、验证来源和结果迁移 | 各领域提供适用的检查证据；Reverse 用原程序输入/分支检查 | G04；V03 |
| F06 | 输入类型与操作前置条件弱 | 通用输入与工具格式契约，保留跨类回退 | ELF 解析和参数恢复由 Reverse 负责；JSON RSA 由 Crypto 负责 | G05；V02 |
| F07 | 错误反馈难以纠偏 | API/依赖/参数/执行错误分类、lineage 参数提示 | 各工具补充实际可确认的格式和依赖信息 | G05 |
| F08 | 低信息重复探索与缺少复核 | 公开任务状态、实验区分目标、上下文绑定的信息复用 | 领域工作流决定高价值检查，如先确认常量再分解 | G06；V02/V04 |
| F09 | 复盘需人工拼接记录 | 每轮 prompt、观察/候选/检查关联、只读诊断 | 领域工具提供可定位的解析/检查证据 | G02/G06；V04 |

因此不应把全部问题归为 Reverse 专有缺陷，也不应把 ELF/RSA 技巧写成所有题型必须遵守的通用步骤。通用层提供生命周期与证据契约；领域层提供定位、解析、算法和成功条件。

## 3. 两条独立修改计划

### 3.1 通用可靠性路线

完整任务、契约和验收见 [Agent 通用可靠性改进计划](agent-common-improvement-plan.md)。

| 轮次 | 交付范围 | 最小闭环 |

| C2 | G02/G03、G04 的检查接入、G05 | 从原始观察到实验、候选检查可追溯；至少两类非 ELF 数据验收 |
| C3 | G06、兼容回归和跨题型评测 | 可独立复盘编排行为，分开报告工程可靠性与真实解题率 |

### 3.2 Reverse 专用路线

完整任务、边界和验收见 [Reverse 专用证据与验证改进计划](reverse-evidence-improvement-plan.md)。

| 轮次 | 交付范围 | 最小闭环 |
| --- | --- | --- |
| V1 | V01、V02 的常量/格式串核对 | 有界读取短字符串和正确地址，区分文件偏移/虚拟地址与提示/参数 |
| V2 | V02 分支核实、V03 原程序检查 | 在 sandbox 内对自建交互 ELF 做候选检查，记录适用分支与局限 |
| V3 | V04 | 共享 helper 兼容回归，分别评价事实提取、模型使用和最终求解效果 |

C1 与 V1 可以分别实施；V1 的观察字段对齐 G02 最小契约即可，不必等待通用系统全部完成。V2 接入 C1/C2 的候选和检查机制。先各完成一条最小闭环，再扩大领域覆盖；这些是工程任务依赖，不要求多 Agent 执行。

### 3.3 与其他题型的关系

- Crypto：参数来源、进制、填充/编码假设及重加密/关系检查属于其领域逻辑；即使参数来自 ELF，也不应进入通用循环。
- Forensics/Stego：包/流、归档成员、图像通道和位序等定位与检查由对应工作流解释，共用 evidence/experiment/candidate 契约。
- Pwn：可复用二进制工具，但协议交互、payload 和利用成功条件是独立的领域能力；不能把 Reverse 输入检查当作已完成 Pwn 覆盖。
- Web：请求/响应和成功条件由工作流解释；HTTP 200 不能被通用层当作解题成功，观察和检查仍受既有授权范围限制。

上述是接口划分和回归设计方向，并非其他真实运行中已确认的问题，也不在本次额外承诺实现全部专用验证器。

## 4. 分开验收，再验证组合（本次未执行）

### 4.1 通用验收

fake/scripted model + 自建非 ELF 数据至少覆盖：明确未解出停止、候选记录后继续、格式不等于正确、实验来源不一致、有限搜索失败、摘要可追溯、API/依赖错误区分，以及取消/预算/报告/严格 benchmark 兼容。

至少使用两个非 ELF 场景证明契约独立于 Reverse。普通 exit 0、HTTP 200、出现可读文本、模型自报成功或多个证据引用，都不能独立获得可信验证。

### 4.2 Reverse 验收

自建 ELF 覆盖：短指数与相邻提示、文件偏移与虚拟地址不同、截断后聚焦读取、真实 scanf 格式、参数调用与成功分支、交互输入及失败也 exit 0。

解析和执行在 sandbox 内，原始附件只读。没有 PE/壳/其他架构验收时，不宣称 Reverse 全覆盖。

### 4.3 组合验收与真实模型评测

用自建 Reverse + Crypto 题目完成：Reverse 提取并引用参数 → Crypto 求解/关系检查 → Reverse 原程序输入检查 → 通用层记录结果并结束。局部实验通过不自动等于可信 oracle 接受。

真实模型对照需要新的明确授权，在相同模型、预算和数据条件下记录重复次数，开发集与 holdout 分开，并按题型报告。比较来源正确性、无依据强结论、猜测候选、检查覆盖、正确停止、最终正确率及成本。

本私有运行可作为人工复盘材料，不把答案、常量或题解注入通用提示、共享记忆或公开 fixture。若要重传内容或执行私有题目，按该次评测授权执行。
