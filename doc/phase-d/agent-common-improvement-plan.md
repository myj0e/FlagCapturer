日期：2026-10-08  
状态：G01–G06 首版工程实现与合成验收完成；7ef2 运行暴露的第二轮任务 G07–G12 待实施；真实模型效果对照未执行。
实施记录：[接口、迁移与验收](agent-common-improvement-implementation.md)。  
来源：[RSA 运行复盘](20261008-rsa-run-review-and-improvement-plan.md)。

第二轮依据：[7ef2 运行的通用问题与增量计划](20261008-run-7ef2-common-agent-followup.md)。已有工程交付保持记录；新增任务用于补齐真实使用中的成本、预算和收尾缺口，不把此前合成验收解释为真实解题效果已达标。

## 1. 范围与设计判断

本次运行暴露的停止策略、候选验证、假设核验、实验来源与日志问题，属于所有题型都可能遇到的 Agent 机制问题。它们在 Reverse/RSA 场景中已有实例，但其他题型发生频率及改进收益尚未评测。

本计划实现共享的编排、证据、候选和诊断契约。ELF 地址映射、指令参数恢复、RSA 运算等由领域工作流提供；通用循环不理解这些算法，不要求每种题目都做反汇编或执行程序。

核心原则：先建立“能够可靠地记录未知答案、正确结束一次尝试”的最小闭环，再扩大到证据核验与跨题型评测。没有 oracle 不是错误，也不要求用户预先知道 flag。

## 2. 通用问题在其他题型中的对应场景

下表是用于设计回归的风险示例，不是已发生的其他真实运行问题。

| 通用缺陷 | Reverse 中的实例 | 非 Reverse 的对应风险 |
| --- | --- | --- |
| 摘要遗漏与原始数据脱节 | 短指数被字符串过滤遗漏 | Forensics 只看部分包、Web 只看响应片段，却推断不存在某项内容 |
| 假设变成事实 | 把成功提示当指数 | Crypto 猜错进制/填充；Stego 猜错通道/位序，却不复核 |
| 复现实验自证错误输入 | 脚本硬编码错误常量 | 使用复制错误的密文、错误 PCAP 流或过期 HTTP 响应验证自身猜测 |
| 不允许明确未解出 | 宣布未解出后被要求继续提交 | 各题型在证据不足时拼接或猜测 flag |
| 候选与完成耦合 | 格式匹配立即结束 | 任意题型里一个诱饵或中间结果阻止后续检查 |
| 工具失败被误归因 | API 导入错被视为环境问题 | 解析失败被当成文件损坏、请求失败被当成服务无漏洞 |
| 缺少可定位的复盘 | 需人工对照多份 artifact | 无法还原模型看到的截断内容、重复尝试与主控继续原因 |

## 3. 通用接口与职责边界

先定义最小数据契约，再由各领域按需扩展；不要求一次性实现全部字段。

| 对象 | 通用层记录/检查 | 领域层补充 |
| --- | --- | --- |
| observation | run、输入/会话来源、artifact 引用、产生它的工具调用、覆盖范围和是否截断 | 如何解析或重查该观察 |
| source locator | 区分文件、会话、受控请求等来源；保留定位信息及其类型 | ELF 虚拟地址、JSON 字段、PCAP 包/流、图像通道/像素等定位方法 |
| hypothesis / claim | 简短公开结论、依据、未知项、矛盾和计划中的检查 | 此题型哪些实验能支持或推翻结论 |
| experiment | 脚本/工具版本、输入来源、实际参数、输出、与假设的关系 | 参数提取与实验语义 |
| candidate | 候选来源、推导说明、检查证据、记录与结束动作 | 二进制输入检查、重加密、协议响应、提取内容一致性等 |
| check | 检查器来源、适用输入/版本、结果和局限 | 领域成功条件，或没有适用检查器的原因 |
| completion | 明确终态、停止原因、未解决项和结果引用 | 面向该题型的下一步建议 |

通用 controller 校验引用存在、属于本次运行及契约结构，不凭“引用很多”或模型自报高置信度判定正确。模型写出的检查器通过也不能自行升级成可信 oracle。现有 controller-only exact oracle 是独立的可信验证来源，继续保持隔离。

## 4. 通用修改任务

### G01：正确结束与继续策略（P0；对应 F04）

涉及 AgentLoop、ModelSession 工具契约、application lifecycle、TUI/报告。

- 增加结构化完成入口，允许 `unsolved`，而不是依赖自然语言终止或必须产生 flag。
- 明确完成后不启动新一轮。没有完成信号时，根据待验证假设/新证据建议下一步；没有合理下一步时允许结束为未解出。
- 区分未解出、预算耗尽、取消、provider/runtime 失败。“模型声称无解”仍只是模型结论，不能被 controller 背书为数学无解。
- 兼容现有 `unverified` 等历史状态，明确新增状态、退出码和报告迁移，不静默改变调用方行为。

验收：fake model 一轮调用工具后明确未解出，主控只结束一次、不再要求猜测候选。相同用例分别使用 ELF、纯文本和自建受控响应；终止语义一致。

### G02：摘要可追溯与按需补充观察（P0；对应 F01 的通用部分、F09）

涉及 EvidenceStore、工具结果公共字段、TUI/报告。

- 摘要必须表明来源、覆盖/过滤条件、是否截断，以及取得相关原始内容的方法；不承诺所有大输出无限保存。
- 允许对同一输入做有界的聚焦查询；选择器由领域工具解释。文件偏移可以共享，ELF 虚拟地址等语义不进入通用循环。
- “摘要未出现”只能说明当前可见范围没有，不能默认推断原始数据不存在。
- 继续沿用每次运行的私有 artifact；不扩大输入、网络或宿主访问范围。

验收：至少用纯文本/JSON 和自建协议响应两类非 ELF 数据，检查过滤/截断标记、证据引用及聚焦读取；Reverse 数据另由专用计划验收。

### G03：假设、实验与来源绑定（P0；对应 F02/F03）

涉及通用求解提示、脚本证据、各工作流的公共约定。

- 维护简短公开的“事实—假设—检查结果—未知项”，不采集隐藏推理，不要求每次工具调用都填写复杂表单。
- 关键实验记录实际输入来源与转换步骤。硬编码参数可用于假设实验，但不能不经核对就声称复现了原题。
- 强结论出现矛盾时优先核对来源；有限搜索失败只能说明该次尝试未找到结果。
- 自动机制首先做来源、输入版本和明显不一致的结构检查；不能宣称通用系统已经能判断任意证明是否正确。

验收：合成密文被错误复制、JSON 字段被混淆、摘要值与原始值冲突等轨迹保留假设状态或产生来源检查失败；不能因脚本 exit 0 就视为已证实。确定性轨迹验证状态契约，真实模型是否主动查证另行评测。

### G04：候选记录、检查和结束分离（P0；对应 F05）

涉及 ToolRegistry、AgentLoop、验证模块及全部结果消费者。

- 候选保存来源、简短推导与已有检查，或明确说明尚无检查。格式判断仍只表示格式，不表示求解成功。
- 记录候选后可以继续检查或改进；结束由显式完成信号或可信验证策略决定，不能天然由一次格式匹配决定。
- 有领域检查器时记录实际结果；没有检查器时允许以未验证候选结束，不强制提供 oracle，也不阻止人工查看猜测候选。
- 区分格式匹配、局部/自编检查、可信 oracle 等验证来源；具体新增字段与状态需版本化，保留历史数据解释。
- 检查不通过时允许继续求解。程序 exit 0、HTTP 200、能解码出文本、模型说“成功”都不是通用成功判据。

验收：同一假候选在 ELF、文本 Crypto 和受控 Web fixture 中均不能仅凭格式成为成功；缺少检查器时保持未验证且可结束；exact oracle 仍只能由 controller 读取。严格 benchmark 分母/成功定义和 CLI 退出码有明确兼容检查。

### G05：输入与错误契约（P1；对应 F06/F07）

- 提供输入类型和工具支持格式；题型标签保持启发式，不禁止混合题，也不把文件名当作格式契约。
- 分开记录输入格式不符、无效参数、API 使用错误、依赖缺失、执行/服务失败。
- 复杂格式解析仍在 sandbox 内；错误提示提供可操作的下一步，不自动安装包或扩大网络权限。
- lineage 等公共参数明确示例和单位，保留原始异常证据。

验收：非 JSON 输入进入 JSON 专用操作时收到格式提示；API 导入位置错误不误报为缺包；错误输入路径/hash 可区分并修正。

### G06：探索进展、完整编排日志与只读诊断（P1；对应 F08/F09）

- 下一步实验说明要区分哪个假设；不把增加工具调用次数当作进展，也不硬性禁止合理重试。
- 可复用的环境/只读快照信息按镜像、输入和运行上下文绑定；会变化的服务响应不能无限缓存，失败后应重新检查适用性。
- 保存每轮实际 controller prompt artifact，关联公开说明、调用、原始输出、模型实际收到的摘要、检查及终止原因。
- 诊断先输出可证实事件和待复查项，不自动把所有解析错误解释为模型推理问题。

验收：只读报告能还原为何继续/结束、模型实际看到了什么和候选检查依据；不执行题目、不调用模型、不暴露凭据，也不采集隐藏推理。

## 5. 分轮交付

| 轮次 | 最小交付 | 完成门槛 |
| --- | --- | --- |
| C1：运行与结果闭环 | G01、G04 的候选来源记录、显式完成和未验证结果语义 | 不依赖 Reverse，未知答案题可正确结束；格式候选不冒充成功，也可继续检查 |
| C2：证据与检查闭环 | G02/G03、G04 的领域检查接入，G05 的格式/错误提示 | 至少两类非 ELF 数据能完成来源绑定和候选检查，假实验不会升级验证等级 |
| C3：诊断与评测 | G06、兼容回归与模型对照方案 | 日志可独立复盘；工程可靠性、领域能力与模型解题率分开报告 |

先完成 C1，不等待所有领域都有自动验证器；C2 先接一条非 Reverse 检查路径，再扩展。C1/C2 已完成首版工程验收；C3 的只读诊断、兼容回归和对照方案已交付，真实模型对照待另行授权执行。此处 C1–C3 是本增量轮次，不重定义项目阶段 C。

## 6. 跨题型验收与效果评测（工程验收完成，真实模型未执行）

- 确定性层：fake/scripted model + 自建数据，验证终止、引用、候选状态、预算、取消和错误契约。至少包括两个非 ELF 场景，不能只用 RSA/ELF 证明“通用”。
- Sandbox 层：自建纯文本 Crypto、归档/JSON、离线或自建受控响应；验证真实工具和资源清理，不访问真实站点或运行私有题目。
- 真实模型层：另行取得该次明确授权，在相同模型与预算下比较改动前后，记录重复次数并按题型分别汇报；开发集与 holdout 分开。
- 通用指标：猜测性候选数、未验证强结论数、来源可追溯率、实际检查覆盖、正确停止率、正确率与成本。不存在检查器的题目单列，不因难验证就排除失败样本。
- 原 RSA 私有运行只作案例证据，不把其答案/题解写入通用提示、公共 fixture 或共享记忆。

工程测试与合成验收使用用户此前明确授予的测试、本机 Docker 和自建端点授权；未调用真实模型或运行私有题目。本计划本身不授予新的模型额度或网络权限。

## 8. 第二轮通用改进：预算、工具成本与正确收尾

依据运行 `7ef2921c-5679-45df-9e09-256af957999c`。模型正确恢复参数且未捏造 flag，但前 60 次调用中，证据查询/实验登记占 15 次，长任务读取占 17 次；第 61 次新执行请求和第 62 次完成请求均被预算拒绝。终态为 `budget_exhausted`，没有得到明文。具体日志证据、归因边界见第二轮复盘。

以下都是跨题型机制问题；仅在本 RSA 案例中观察到，不宣称所有题型都已发生。N 的分解方法、专用分解器缺口及 RSA 弱点选择归属 Crypto，不纳入这些通用任务。

### G07：可见且区分用途的预算（P0）

关联 G06；涉及 AgentLoop、工具结果公共字段、TUI/报告和诊断。

- 明确区分新增求解执行、证据/进度观察、停止/完成控制。记录各类消耗和剩余量，不再只有一个对所有调用一视同仁的计数。
- 先交付预算反馈与临界提示：每次回复提供执行/观察剩余额度和剩余时间，支持模型安排批次、验证与收尾。临界阈值和保留空间写入运行快照，不靠模型猜剩余次数。
- 统一记录请求数、获准处理数、实际执行数和拒绝数，不能把拒绝请求计为已执行任务。历史 `tool_calls` 含义保持可解释。
- 观察操作仍有次数、速率、输出和时间上限；不得通过免费轮询无限消耗模型调用。`session_send` 或能触发新的计算/请求的工具不能伪装成免费观察。
- 预算分类和成本由 controller 的已知工具契约决定，不接受模型自行指定成本或类别。统计权重/独立额度需记录并验证，不能借此绕过整次运行预算。

验收：纯文本解码、归档处理、自建协议会话使用同一预算语义；达到执行限额后不能新建脚本计算，却仍能按有界策略观察/停止已有任务和完成记录。请求、拒绝、执行计数可独立核对；大量无输出轮询仍会被限流/限额。

### G08：预算耗尽后的完成与清理通道（P0）

关联 G01/G04；涉及 dispatch、run_complete、会话停止、lifecycle 和结果消费者。

- `run_complete` 不因求解执行额度耗尽而被同一闸门拒绝；允许有界、幂等的摘要保存和已有资源停止。
- 保留客观停止原因 `budget_exhausted`，另行保存模型报告的 `unsolved`、未完成事项和证据引用。不能用主动完成覆盖预算、取消或运行错误而伪造正常成功。
- 时间/provider 已耗尽或失联时，由 controller 按已保存证据自动收尾，不要求额外调用模型补写摘要；缺失的模型结论明确记为缺失。
- 收尾通道只接受有限元数据与运行所属资源的停止，不运行任意脚本、不发送新的交互输入、不发起网络请求。总时限后的清理宽限必须有限且单独记录。
- 一次终止只产生一个最终状态，重复完成幂等或明确拒绝；取消和 cleanup failure 的优先级保持可追溯。

验收：恰好耗尽执行次数后调用完成工具，摘要仍保存，stop_reason 仍为预算耗尽；无模型回复时也能结束并清理。测试重复完成、取消竞态、异常清理和试图借收尾启动新计算，不能产生双重终态或越权执行。

### G09：来源绑定自动化与可修正的参数错误（P0）

关联 G02/G03/G05；涉及 observation、experiment_record 和 schema。

- 聚焦读取返回可复用的、run-local 来源引用，封装 artifact、选择范围、hash 和上下文；模型主要填写参数名、实际值及语义说明，不手抄整套路径/偏移/hash。
- 在 server 端重新验证引用所属、输入版本和范围，不能因减少手填字段而弱化来源校验。
- 明确区分原输入坐标与选中字节 artifact 的坐标，参数名称与参数值。建议用 `parameter_key` 等无歧义字段名；旧 schema 的迁移需要兼容说明。
- 缺少必要语义说明时保留假设等级，不自动替模型猜参数角色或补造证明；原参数正确与脚本实际使用了参数仍是两个不同结论。
- 错误回复指出具体 binding/字段、期望格式和一个使用实际返回引用的最小修正示例；聚合可安全列出的错误，避免每改一处才发现下一处。
- 支持复用已经验证的参数集，给多个真实执行 observation 登记结果时不重复填写同一来源。

验收：在 JSON 字段和纯文本字节两类非 ELF 用例中，来源绑定不需要额外 observation_get 即可完成；故意填错参数名/路径后一次明确修正可成功。跨运行、过期来源、改动 hash 和参数值不一致仍被识别；自动绑定不能升级为语义证明。

### G10：低成本的长任务观察（P0）

关联 G07；涉及 session_read、后台任务状态、TUI 和 provider 工具契约。

- 支持合并进度和更长的有界等待，或等价的完成/状态变化通知；不要求每 10 秒由模型消耗一次普通求解调用。
- 高频心跳可显示在 TUI/保存 transcript，而无需每条都驱动 LLM。模型只在约定观察点、状态变化或异常时决策。
- 等待同时受剩余运行时间、观察预算和输出上限约束，取消应可中断；静默时长由最近实际输出计算，读取操作不能把它重置。
- 不把每次无输出都当成阻塞或无效操作；记录其成本，按任务预期允许继续、降低频率或停止。
- 继续保证完成/失败能及时被观察，不能为了降低次数把错误、因子/候选结果或关键进展藏到总超时之后。

验收：自建超过 120 秒的任务带周期心跳，默认观察策略在不超过 6 次模型读取内获取终态；另测静默任务、异常退出、输出溢出和用户取消。该阈值适用于固定合成场景，不能宣称所有真实任务均只需 6 次观察。读取总时长/输出/请求限额仍有效，停止延迟有记录。

### G11：便宜检查优先、能力感知与分阶段实验（P1）

关联 G03/G06；涉及通用实验规划和领域工作流接入。

- 领域工作流为方法提供适用条件、所需能力、廉价前置检查及可观察进展；通用层只使用这些契约，不内置 RSA 或其他题型算法。
- 先做能区分假设的廉价检查，再投入昂贵批次。多次失败后说明继续加预算的依据，或改变方法/明确记录能力缺口。
- 库函数内部未必有工作上限；耗时阶段使用独立有界执行或主动 deadline/检查点，避免首个无界步骤阻止脚本后续所有方法执行。
- 静态输入和环境信息按现有上下文复用；重复同一方法时记录种子/参数变化，避免误把重复尝试当新方法。
- 缺少能力可以未解出结束，不自动安装环境、不扩展网络，也不能推断题目无解。能否补专用工具由对应领域另行评估。

验收：自建归档/解码/受控请求任务中，廉价可判别检查先于昂贵循环；无界库调用由外层预算结束且保留部分证据。故意缺少某领域能力时正确报告缺口，不伪称损坏/无解；没有证据时不要求必须升级计算。

### G12：实际执行状态与模型说明一致（P1）

关联 G06；涉及工具结果摘要、后台任务状态和只读诊断。

- 工具状态明确区分：已完成、已超时、后台运行中、仅登记成功、执行被拒绝。返回预算和下一步动作应与当前状态一致。
- 前台调用已返回 timeout 时，不再描述成该命令仍运行；后台运行状态必须关联真实 session，而不是从脚本描述推测。
- 诊断按时间线提示可证实的状态矛盾；模型说明仍作为公开文本保留，不重写历史或把文字错误升级成运行时事实。

验收：前台超时后紧接后台成功/失败等轨迹，状态摘要与日志一致；超时结果不能被误标为进行中或成功。关于模型是否据此正确表述，需要真实模型评测单列，不以 fake 输出声称已改善推理能力。
