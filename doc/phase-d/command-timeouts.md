# 命令超时与长任务脚本

## 当前语义

- `command_run`、`script_run`、工作流命令的超时是**总经过时间**，默认 120 秒；输出进度不会延长这个时限。不是按静默时间判断脚本阻塞。
- 默认 `ctfbot-tools` 镜像有 Python/Linux `/proc`。命令在独立进程组和 subreaper 下执行；超时会终止本次命令并清理其子孙进程，包括脱离进程组的后台进程。清理成功返回 `timeout` / exit 124，容器和 `/work` 保留，Agent 可以继续。
- 正常命令结束也清理其后台子孙进程。需要跨工具调用保留进程时使用交互会话工具。
- 控制器额外保留最多 5 秒命令监管/传输宽限。监管失效、无法确认子进程清理、输出管道不关闭时仍关闭整个沙箱。旧版无 Python 镜像只能使用控制器超时并关闭整个沙箱的兼容路径。
- 沙箱关闭后解题循环立即停止，状态为 `error` / `sandbox_closed`；取消模型调用并走既有清理流程。TUI 明确显示沙箱关闭，不再持续调用不可用环境。
- 交互会话原有静默/总时限仍有效；其强制清理若关闭沙箱，也在后续工具调度或模型回合结束时检查并停止。

## 给模型的脚本约定

### 超过 120 秒的脚本

新增 `script_start(path, argv)`：沿用 `script_save` 的源文件 SHA-256 校验，后台启动后立即返回 `session_id`。执行时间受整次解题剩余预算约束（最多 1800 秒），不受普通命令的 120 秒限制。

模型使用 `session_read(session_id, wait_seconds)` 增量读取输出；返回 `elapsed_seconds` 和 `output_idle_seconds`，分别表示运行时长与距离最近输出的时间。读取操作不会将“最近输出”时间重置。TUI 同时显示两个时间。

后台脚本不会因 60 秒无输出自动关闭；模型结合进度、静默时长、算法预期成本和剩余预算决定继续等待或 `session_close`。关闭时命令监管程序接收中断、清理脚本子孙进程，正常情况下保留沙箱和 `/work`。清理失败仍走关闭沙箱的兜底路径。普通交互会话的原有 60 秒控制器空闲 / 600 秒总时限保持有效。

总运行预算、工具调用次数、会话数和输出上限仍独立生效。该机制不允许无期限运行；最终等待/停止策略由模型决定，并不保证模型一定判断正确。后台监管保留 exit 125 作为必须关闭沙箱的失败信号。

初始提示词和 `script_save` 描述要求：

1. 昂贵任务每 5–10 秒输出简短进度，例如已完成量/总量、耗时、当前最佳结果；使用 `flush=True`。`script_run` 默认使用 Python `-u`。
2. 循环、外部子进程都设置边界和超时。将搜索拆成可恢复的小批次，在工具时限前留余量退出。
3. 在 `/work` 保存检查点和中间结果；下一次调用从检查点继续。需要保留到运行结束之后的结果仍使用 `artifact_export`。
4. 普通命令/脚本输出在工具返回后展示；长脚本用 `script_start` / `session_read` 增量观察，由模型决定是否继续或停止，避免高频空轮询。

提示词只能引导模型，不保证每次生成的脚本都会遵守；运行时仍独立执行时限和清理规则。
