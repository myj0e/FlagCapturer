# Reverse 专用证据与验证改进计划

日期：2026-10-08  
状态：待实施；本次只设计文档。  
来源：[RSA 运行复盘](20261008-rsa-run-review-and-improvement-plan.md)。  
共享机制：[Agent 通用可靠性计划](agent-common-improvement-plan.md)。

## 1. 哪些问题是 Reverse 专用的

本次“漏掉短字符串”的一般问题是摘要覆盖不足；其 Reverse 专用修复是带位置的二进制字符串、ELF 地址映射、原始字节检查和引用关系核实。

通用的“关键事实需要证据”在 Reverse 中具体表现为确认参数地址、进制、寄存器/调用约定、格式串、比较和成功分支。通用的“候选应检查”在 Reverse 中具体表现为对原程序的受控输入输出检查。

RSA 运算属于 Crypto 能力，即使它的参数来自 ELF，也不应被硬编码进 Reverse 通用框架。本次题目是 Reverse 提取参数 + Crypto 求解/检查的组合。

## 2. 范围与非目标

- 首批支持已有 ELF 分析路径，解决字符串位置、地址映射、调用参数及候选原程序检查。
- PE、壳、反调试、其他架构、反编译器覆盖另列能力扩展，不能由这次 x86-64 ELF 验收推定完成。
- 原始附件仍只读；解析和执行都在 sandbox 内。controller 不解析不可信 ELF、不执行题目，不增加 Docker 权限。
- 不把通用运行循环改造成 ELF/RSA 解题器，不要求其他题型执行 ELF 流程。

## 3. 专用修改任务

### V01：带位置的字符串与字节查询（P0；F01 的领域实现）

涉及 `packs/scripts.py`、Reverse/Pwn ELF 工具、共用二进制 triage。

- 字符串结果携带文件偏移、长度、原始/安全显示内容和提取条件；短字符串可以按需查询，避免低阈值刷屏。
- ELF 通过已校验的节/段信息映射虚拟地址与文件偏移；两者分别标记，映射失败明确报错。
- 提供有界的文件偏移/虚拟地址/节查询，检查 NUL 边界及相邻常量；禁止悄悄改按另一种坐标解释。
- 显式返回范围、过滤和截断信息，接入通用 observation/source locator 契约；完整证据仍按现有上限私有保存。

验收：自建 ELF 含五字符数字指数、长成功提示、三字符失败提示和 `%99s`，四者均准确定位；另有文件偏移与虚拟地址不同的 fixture。越界、不支持格式和截断均明确反馈。二进制字符串工具可复用于 Forensics/Pwn，但 ELF 坐标语义留在领域层。

### V02：参数、引用和分支核实流程（P0；F02/F06 的领域实现）

涉及 Reverse 工作流指导及有界反汇编/读取工具。

- 在从反汇编恢复参数时，核实调用处引用地址、参数角色、数据格式和实际字节；不要把字符串列表的排列当地址映射。
- 对密码学参数区分 ciphertext/modulus/exponent 等角色，再交给 Crypto 工作流；参数缺失时先取证，不用邻近提示代替。
- 在“输入漏洞”“附件损坏”“无解”前检查真实格式串/输入宽度/关键分支；无法确认时记录假设和检查缺口。
- 反汇编过长时支持聚焦代码范围，保留原始输出引用和截断提示；不自动承诺已恢复所有控制流。

验收：合成运行轨迹能区分指数引用和成功提示引用；`%99s` 不被工具报告为不受限 `%s`。fake 轨迹检查证据契约，真实模型正确使用工具的比例另行评测。

### V03：原程序候选检查（P1；F03/F05 的领域实现）

涉及 command/session、保存脚本与领域检查证据，不重写现有运行时。

- 使用同一输入快照和原始程序，记录启动命令、候选输入的编码/换行、实际输出、退出状态与适用分支证据。
- 交互式程序用 session 或 sandbox 内的有界驱动脚本；原附件不可执行时在 `/work` 建立 hash 可核对的副本，不修改原始快照。
- 成功/失败判定依据来自已核实的程序路径；不能只凭 exit 0、任意出现“success”或模型猜测成功文本判定答案正确。
- 区分“原程序检查”“修改过的程序/模拟检查”“自编假设实验”。patch 或重建程序的成功结果不能直接替代原附件验证。
- 记录检查器来源、输入版本、观察与局限；是否获得可信 `verified` 由通用验证契约决定，模型不能自行升级。
- 无法安全自动检查时允许以未验证候选/未解出结束，不能把检查能力缺失判为题目无解。

验收：自建交互 ELF 对正确/错误输入分别输出受控分支；错误输入也 exit 0，仍不能误判成功。错误候选可继续检查；检查流程保留沙箱预算、日志和清理行为。原文件 hash 不变。

### V04：Reverse 效果与兼容回归（P1；F08/F09 的领域实现）

- 记录常量/角色提取正确性、地址混淆、格式串误读、候选原程序检查覆盖和失败归因。
- 冻结与共享的二进制 helper 契约并检查 Pwn/Forensics 调用兼容；不因为本题修复而改变所有类别的成功标准。
- 将工具是否正确返回事实、模型是否正确使用事实、最终是否解题成功分开统计。

验收：ELF helper 正确性有确定性用例；模型实验有独立重复次数和 holdout。无 PE/壳/其他架构数据时，不宣称 Reverse 全覆盖。

## 4. 分轮交付与依赖

| 轮次 | 最小交付 | 对通用计划的依赖 | 完成门槛 |
| --- | --- | --- | --- |
| V1：证据可见 | V01 + V02 的常量/格式串核对 | 无需等待通用完成工具；先按 G02 最小字段约定设计 | 准确读取短指数与相邻提示，不混淆文件偏移/虚拟地址 |
| V2：原程序检查 | V02 的分支核实 + V03 | C1 的候选/完成契约及 C2 的检查记录 | 自建交互 ELF 的真/假候选可检查并正确记录；不是 exit 0 即成功 |
| V3：领域评测 | V04 | C3 的日志和评测基础 | 共享 helper 无回退；工具、模型和解题效果分别报告 |

V1 可与通用 C1 分开实施；这是任务依赖关系，不要求并行启动多个 Agent。V2 复用已有 session/脚本能力，先完成一条交互 ELF 检查闭环，再逐步扩大覆盖。

## 5. Reverse + Crypto 组合验收

使用自建、可控规模的 RSA 校验 ELF，而非复制原私有题目：

1. Reverse 工具从原附件读取 `N/e/C`，记录来源与原始表示。
2. Crypto 逻辑根据显式参数求解或进行候选关系检查，记录进制、字节序、编码和适用假设。
3. Reverse 通过原 ELF 对候选进行受控输入检查，记录分支依据。
4. 通用层保存全部证据、候选和完成状态；其中任何一层的局部成功不自动等于可信 oracle 接受。

加入诱饵：成功提示看起来像 flag、短指数不在初始摘要内、硬编码错误常量以及失败也 exit 0。先验证确定性工具/契约，再在新授权下开展真实模型对照。

其他题型的专用工具或验证器不在本文件中提前承诺。共用契约由通用计划负责，新增领域实现由对应工作流单独提出范围与验收。
