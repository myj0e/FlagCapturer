# Agent 上下文管理改进计划

日期：2026-10-08  
状态：CM01–CM06 已实施；代码、确定性测试与 Docker 验收见[实施记录](agent-context-management-implementation.md)，真实模型效果对照未执行。
关联：[通用可靠性计划](agent-common-improvement-plan.md)、[实施记录](agent-common-improvement-implementation.md)。

## 1. 目标与交付顺序

先完成“忘记了也能找回”的最小闭环，再改善长输出和预算，最后接入模型侧上下文观测及压缩恢复。各阶段独立验收，上一阶段可正常使用后再扩大范围。

完成后的目标行为：模型在长时间求解中可以找回题目约束、公开方案、原始证据、失败实验、脚本和活动进程；关键状态不依赖完整对话始终可见。用户可区分摘要过时、工具输出预算不足、上下文占用未知以及发生过压缩。

恢复只针对同一次运行中仍然存在的 controller、sandbox 和证据。跨运行记忆沿用已有显式授权机制。进程崩溃后恢复 Docker、自动重启模型线程和跨进程续跑单独立项；本次不能因此把 `resume_supported` 改为 true。

## 2. 设计编写时的现状与依据

| 当前实现 | 缺口 | 对应任务 |
| --- | --- | --- |
| CodexModelSession 复用同一 thread | 项目不观测上下文容量、压缩过程，恢复依赖 provider 历史 | CM05、CM06 |
| summary_update 保存公开摘要及版本 | 无摘要读取入口；续轮只列 candidate/claim ID | CM01、CM02 |
| observation、claim、experiment、candidate 在 controller 中保存 | 缺少统一索引与按 ID 获取完整记录的入口 | CM01 |
| 脚本保存在 domain 工具的局部 saved 映射；session 在 registry 中登记 | 遗忘路径/ID 后难以枚举；状态可能只是历史记录 | CM01 |
| 工具回复超长时截取前缀并保存 artifact | 尾部结论可能不可见；再次回读增加预算消耗 | CM03 |
| 累计工具返回默认限制为 256 KiB | 与模型上下文容量没有直接对应关系；恢复与整理也消耗该额度 | CM04 |
| 未消费的 App Server 通知留在无界队列 | 长会话重复扫描、事件积累，缺少丢弃策略 | CM05 |

已确认的是项目代码没有处理这些能力；不能据此断言 Codex 自身不会压缩。后续 provider 能力以本机安装版本的 schema 和真实事件为准，模拟事件不能当成 API 已支持的证明。

## 3. 状态、摘要与证据的职责

采用三层结构，避免把右侧摘要当成唯一记忆。

1. **运行状态索引**：controller 自动维护，记录运行约束、脚本、检查点引用、session、候选、实验和证据位置。只描述实际记录过的操作与可观测状态。
2. **公开解题摘要**：由模型维护，包含目标、线索、假设、方案、下一步、阻塞和更正。始终标注 model_reported，不自动成为事实证明。
3. **原始证据**：现有 hash artifact 和事件日志，按需读取。摘要遗漏不能证明源文件不存在相应内容。

索引仅引用本轮已准入输入和已登记对象。oracle 已按代码整理要求退役；任意 controller 路径以及未经授权的其他运行不进入快照。脚本保存状态与进程当前运行状态分别记录；历史 session 成功启动不等于现在仍在运行。

## 4. 阶段一：建立可找回状态的最小闭环（CM01–CM02，P0）

### CM01：运行状态索引与统一读取工具

涉及：新增 `src/ctfbot/agent/context.py`；修改 `tools/reliability.py`、`tools/domain.py`、`tools/registry.py`，复用 EvidenceStore。

交付：

- 定义 `RunContextState`，以 run_id、schema_version 和单调递增 revision 标识快照；证据落盘保存可恢复索引。现有候选、观察、实验记录继续作为来源，避免再维护一套可分歧的数据。
- 将脚本登记表从 domain 闭包移为可查询的运行内对象，记录路径、hash、来源、创建工具调用和最近执行引用。
- session 索引保存 ID、类型、启动参数摘要、最近状态及 observed_at。提供 live / historical / unknown 标记；没有新观察时不声称进程存活。枚举不会读取并消耗待取进程输出。
- 增加 `state_read` 工具，提供 `overview`、`summary`、`observations`、`claims`、`experiments`、`candidates`、`scripts`、`sessions`、`checkpoints` 分区。
- 使用 section + 可选 id + 可选 cursor 分别读取概览、单对象和分页列表，首版每页最多 20 项，回复最多 8 KiB UTF-8。cursor 绑定分区和快照版本；索引变化后返回明确的游标过期信息。
- 有 ID 的对象可直接取记录；summary 可读 latest 或指定版本。返回 revision、来源引用和缺失/过时标记。候选正文保持私有证据路径；模型只可读取本轮已提交候选。
- 恢复工具的返回不再作为新的“解题进展”允许重复 summary_update；避免读状态 → 更新摘要 → 再读状态的无效循环。
- 首版检查点仅登记已有导出 artifact 或脚本明确返回且经过存在性/来源检查的引用。不自动扫描任意 /work 内容，也不靠模型声称文件存在。

验收：

- 模拟模型完全忘记前文，仅拿到 run_id 和 `state_read` 工具后，可以找回最新方案、失败实验、脚本与 session ID，再执行正确的下一步。
- 缺失 ID、错误分区、越界/过期 cursor、不同运行的引用返回明确错误；不读取其他运行文件或任意 controller 路径。
- 删除模型摘要不影响 controller 索引；无 summary 的旧日志仍可显示已记录资源。
- 1000 条观察/实验记录下分页可用，单次返回始终有界，不把全部记录塞入提示词。

### CM02：续轮与显式恢复时提供状态快照

涉及：`agent/loop.py`、新增 context 模块、`model_adapters/protocol.py` 的行为契约及合成 provider。

交付：

- 首轮说明 state_read 的用途，稳定规则与本轮题目/用户提示分区表达；明确外部文件、工具文本和模型摘要是数据或待检验陈述。
- 将续轮提示改为“完成规则 + 有界状态快照 + 读取入口”，包含题目/授权约束摘要、最新解题摘要、关键对象 ID、活动资源状态、剩余预算和未解决项。
- 首版自动快照最多 8 KiB，按优先级保留约束、最新方案、阻塞、活动 session、当前脚本/候选及证据索引；省略字段明确列入 omitted_sections，并给出 state_read 的取回方式。
- 重要长参数保留可验证引用与表示方式，不从显示摘要拼凑原值。恢复后执行实验前，需要时重新读取原始 bytes/source_ref。
- 每次实际注入的快照保存 artifact、revision、字节数与原因，能复盘“模型到底收到什么”。
- provider turn 可以覆盖多次说明和工具调用；续轮快照只解决 turn 边界恢复，轮内压缩恢复由 CM06 补齐。

阶段一完成定义：合成 provider 故意遗忘前文后，仍能通过快照与 state_read 继续原任务，不重复已经排除的实验，不丢失脚本和进程 ID。预算仍沿用现有机制，其边界由阶段三改善。

## 5. 阶段二：改善长输出的可见内容（CM03，P1）

涉及：`tools/registry.py`、`tools/reliability.py`、`agent/loop.py`、各工具返回适配；不解析通用自然语言来判断答案正确。

交付：

- 统一有界工具回复结构：工具状态、错误类型、exit_code、session_id、关键结构化字段、stdout/stderr 头尾片段、截断信息和原始证据引用。
- 分别保留 stdout 和 stderr，不让大量进度覆盖尾部错误或最终结果。预算不足时优先保留状态与恢复引用，再缩减头尾片段。
- JSON 工具结果按字段裁剪，不从原始 JSON 字符串中截出半个字段；普通文本采用头尾片段。声明省略的字节范围和编码，避免把两个片段误当成连续文本。
- 为证据读取增加有界 tail 和字面量定位模式，返回匹配附近字节、偏移、总命中数/是否只扫描部分内容。首版限制扫描大小和返回数量，不支持任意正则或任意路径。
- 避免 registry 与 loop 连续截断后形成多层 JSON preview。保存原始证据与实际模型可见回复，保持清晰的对应关系。

验收：最终候选/错误位于大输出末尾时，首次返回可见尾部；二进制、跨 UTF-8 字符边界、空输出、巨大单行及多处匹配不越界。回读能精确取回遗漏字节，引用 hash 验证有效。

## 6. 阶段三：分清输出预算和上下文占用（CM04，P1）

涉及：RunLimits、AgentLoop、CLI/TUI、报告及诊断。

交付：

- 明确 `tool_reply_bytes` 表示累计发给模型的工具回复量；prompt、工具参数、公开说明与 provider token 使用分别统计，不以字节估算冒充精确 token。
- 保留单次输出上限和运行资源限制；旧 `total_model_output_bytes` 配置保留兼容解释，报告写入版本和明确语义。不能把旧数据直接改称上下文窗口大小。
- 累计回复预算达到 80% 时降级为更短回复并提醒，不立即丢掉状态/证据引用。
- 设计独立、有硬上限的恢复和收尾额度，首版建议恢复 32 KiB、收尾 8 KiB；state_read 与聚焦原始证据读取可用恢复额度，普通执行不能借此绕过预算。额度单独声明并审计，不隐式无限放宽旧限制。
- 恢复额度耗尽时明确建议保存候选或结束；保留 run_complete、取消和 session 清理路径。错误/拒绝回复也记入实际传输遥测，防止无效轮询绕过计数。
- 不根据压缩事件重置累计传输预算。工具计数继续只有默认计数，不恢复 60 次上限。
- 启动默认额度是否调整，依据固定合成长任务的测量结果决定；在验收前不宣称取消了输出预算限制。

验收：普通额度耗尽后仍能有界找回关键状态并明确结束；恢复池不能启动命令、创建进程或绕过 wall time。新旧配置、CLI 退出码、报告解释一致。遥测缺失显示 unknown，不能显示 0% 占用。

## 7. 阶段四：观测 provider 与压缩后的恢复（CM05–CM06，P2）

### CM05：规范 provider 事件和队列生命周期

涉及：`model_adapters/codex_app_server.py`、`codex_session.py`、`protocol.py`、证据事件、TUI 状态。

- 根据本机 Codex CLI schema 确认可用 token/压缩事件及字段，建立适配器能力声明；不假定所有版本支持主动压缩或同一事件结构。
- 归一化 context_usage、compaction_started/completed、provider_error 事件。记录 thread/turn、序号、时间、可用计数及容量来源，避免将累计 token 消耗除以上下文容量作为当前占用率。
- 区分累计账单 usage、当前上下文 token、缓存 token、剩余窗口容量。未知字段不猜测；累计 total 与逐轮 delta 按已确认语义统计，避免重复相加。
- 非任务通知及时消费；状态快照类事件可合并为最新值。为队列设置边界与清理策略。
- tool RPC 和 turn 终态不能被普通队列淘汰；溢出时优先清理可合并/已过期通知，对无法安全保留的关键消息显式报错。未知 server 请求须按协议回复，不无限滞留。
- TUI 区分“占用未知”“已收到压缩事件”和“已恢复状态”；不显示未经观测的压缩次数。

验收：混合工具调用、公开消息、usage 和压缩事件的长流中，工具请求恰好响应一次，终态不丢，内存队列有界。错误 thread/turn 事件不能污染当前任务。仅合成测试不能证明安装版本已支持该能力。

### CM06：压缩后重新提供关键状态

涉及：provider 事件桥接、AgentLoop、context 模块、证据和 TUI。

- 观测到压缩完成后标记 pending_restore，生成最新 controller 状态快照；将其加入下一次正常工具回复的独立 context_restore 字段，或下一次续轮提示。
- 恢复内容清楚标注来源、revision、模型报告与 controller 观察的区别；实际注入计入输出预算并保存证据。
- 同一压缩事件只安排一次恢复；连续压缩可合并为最新 epoch。并发回调只入队，由主循环顺序处理，不重入工具 handler。
- 没有后续工具调用/续轮时，只显示尚未送达，不宣称恢复成功；不发送未经支持的异步提示接口。
- 不支持压缩事件的版本依赖阶段一 state_read 和续轮快照。首版不强制开启自动主动压缩；主动压缩需要本机能力确认与另行验收。

验收：单个长 provider turn 中穿插多次工具调用与压缩，压缩后仍能取得原题约束、最新方案和资源 ID；重复事件不反复注入，预算不足时仍保持回复结构有效。没有压缩通知时不得伪造恢复事件。

## 8. 验收矩阵与发布门槛

| 用例 | 必须观察到的结果 |
| --- | --- |
| 无摘要/旧日志 | 索引可读，缺失字段明确，不依赖新事件才能回看 |
| 多轮及单个长 turn | 都能按各自恢复路径找回状态 |
| 上千条实验与撤回 | 分页有界，失败和矛盾保留，旧结论不被自动升级 |
| 长 stdout、尾部答案、stderr 报错 | 状态与头尾可见，原文可定位回读 |
| 进程已退出或 sandbox 丢失 | 不把历史 ID 标成运行中，不自动重建资源 |
| 普通/恢复/收尾额度边界 | 三种额度各有硬上限，完成与清理仍可达 |
| usage 缺失或版本差异 | 能力降级明确，不伪造上下文占用 |
| 压缩与重复/乱序事件 | 恢复有版本、可去重、可确认实际送达 |
| 候选及来源保护 | 候选正确性保持 unverified；其他运行和任意 controller 文件不进入上下文 |
| TUI/报告/回放 | 能对照模型实际可见回复、恢复快照及终态 |

执行方式：先单元和确定性 provider 回归，再使用自建数据验收真实 Docker 中脚本/PTY/检查点状态找回。调用真实模型的效果对照作为独立验收，需明确题目、调用额度和授权；合成通过不能当作解题率提高。

阶段一先交付；其后的任务每完成一阶段更新实施记录和剩余项。测试数量和验收回执只在实际完成后填写，计划中的验收不得标记 passed。
