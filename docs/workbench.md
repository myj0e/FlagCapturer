# 交互工作台

运行环境：Node.js >=22.19、已安装的 Pi 1.1.0 SDK。解题还需要 Docker 和本地工具镜像。项目目录下执行：

```sh
npm start
# 也可以直接打开已有 workspace
node src/cli.js ui data/imports/<snapshot>
```

无参数启动与 `ui` 使用同一工作台；非 TTY 环境使用 `solve` 等 CLI 子命令。`solve --interactive` 保留简单的行式输入，方便已有脚本继续使用。

## 布局与操作

```text
FlagCapturer · 解题中 · 当前题目
服务 / 模型 · 思考强度
┌───────────────────────────────────┬─────────────────────┐
│ 公开说明、补充线索                 │ 解题进展            │
│ 工具执行与完成事件                 │ 目标、线索、假设    │
│ 上下文压缩、重试、最终结果         │ 下一步、阻塞、候选  │
│                                   │ 文件用途与来源      │
└───────────────────────────────────┴─────────────────────┘
耗时 · tokens · 上下文占用与窗口 · 工具调用 · 候选数 · 估算费用
快捷键提示
─────────────────────────────────────────────────────────
> 多行输入
─────────────────────────────────────────────────────────
```

宽度不足 110 列时收起侧栏，状态与结果仍可通过命令查看。极小窗口使用紧凑显示。模型说明按流展示；隐藏推理不展示，完整工具输出保存在运行证据中。主区保留有界的最近记录；报告与历史证据保存于磁盘。

Enter 发送，Shift+Enter 换行。Ctrl+P 打开可搜索操作菜单；菜单输入文字过滤、方向键选择、Enter 确认、Esc 返回。F3 切换日志与右侧摘要的浏览区域，PgUp/PgDn 翻页；窄屏按 F3 或输入 `/summary` 打开完整摘要，方向键/PgUp/PgDn 浏览，Enter/Esc 返回。Ctrl+C 取消认证/输入、停止运行，空闲时退出；Ctrl+Q 或 `/quit` 等待清理后退出。工作台使用独立终端屏幕，退出恢复原终端。

## 输入补全

主输入框复用 Pi Editor、CombinedAutocompleteProvider 与原生补全列表。输入 `/` 展示工作台命令，继续输入可模糊筛选；方向键选择，Tab 插入，Esc 关闭。Enter 沿用 Pi 交互：命令名补全可直接选中并提交，参数/路径候选通常先插入，再按 Enter 发送。

- `/login op`：补全 provider ID；输入 `/login openai ` 后可补全 Pi 声明支持的 `oauth` / `api_key`。
- `/model <查询>`：按 provider、模型 ID 或模型名称筛选，插入 `provider/model-id`，发送后选择对应模型。也可 `/model <provider>` 打开该服务的模型菜单。
- `/thinking <查询>`：只补全当前模型支持的思考档位，发送后应用；运行中修改在后续请求生效。
- `/import ./`、`/network ./`、`/memory ./`：补全文件和目录；后两者还可补全 `off`。文件名含空格时自动加双引号，目录补全后可继续输入下一层。支持绝对路径与 `~/`。
- 普通文字中的 `@路径`：补全路径引用。引用作为文本插入，附件的实际导入与模型传输授权仍通过 `/import` 完成。

补全以启动项目目录为基准，枚举文件名，不读取文件内容。工作台会查找 Pi 已缓存或 PATH 中已安装的 fd/fdfind，存在时使用 Pi 的递归模糊文件搜索；没有时沿用 Pi 的单目录路径补全，可逐层浏览，不自动下载工具。主输入框提供补全，认证窗口中的 API key/登录码输入保持遮蔽。

补全列表会随终端高度调整；窄窗口优先保留光标与当前候选。极小窗口仍使用紧凑输入布局。

## 配置服务、模型与思考强度

1. `/login` 选择服务，再选择该服务实际支持的 API key 或 OAuth 登录方式。环境认证型服务提示配置环境变量或 profile。OAuth 按 Pi 的 auth_url/device_code 通知自动尝试打开系统浏览器，同时显示完整链接、设备码或人工回填提示，具体授权与本地回调流程由 Pi 的 provider 决定。等待窗口可用方向键/PgUp/PgDn 浏览长链接，Enter 重新打开浏览器；没有桌面环境时复制链接到浏览器完成登录。Esc 或 Ctrl+C 取消认证。
   支持 `/login openai` 直接定位 OpenAI，默认选中 Pi 的 `Sign in with ChatGPT`；`/login openai oauth` 直接进入浏览器认证，`/login openai api_key` 直接输入 API key。服务名称和认证方式均来自 Pi，不维护第二份 provider/OAuth 实现。
2. `/model` 搜索服务和模型。列表显示模型 ID、文本/图片能力、上下文窗口。也能发现 Pi 已有 models.json 中的服务。
3. `/thinking` 只显示该模型在 Pi 中声明支持的档位；非思考模型只显示 off，xhigh/max 仅在模型支持时出现。运行中修改在后续请求生效。更换服务/模型需要先停止运行。

配置工作台不发送测试模型请求。显示的“已配置”表示 Pi 找到认证来源，并不代表已验证远端额度或模型可用性。

自定义兼容 API 使用 `/endpoint`，依次填写名称、Base URL、协议、模型 ID、思考/图片能力和 token 上限，再通过 `/login` 配置 API key。支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 协议。Base URL 不接受 URL 用户名、密码、查询参数或 fragment；密钥在独立的遮蔽输入框填写。复杂请求头和 provider 差异仍通过 Pi models.json 配置。自定义服务价格未知，费用显示不能用于结算；其他服务显示 Pi 的估算值。

认证直接调用 Pi ModelRuntime.login/logout，共用 Pi 的凭据存储。API key、人工登录码以星号显示，不进入工作台日志、题目提示词、证据或非敏感配置。OAuth URL/设备码仅在认证窗口展示，完成或取消后清除。`/logout` 会移除 Pi 中该服务的已保存凭据，影响使用同一存储的 Pi；环境变量保持不变。

模型、思考强度、镜像保存在 `data/settings/preferences.json`；工作台自定义端点保存在 `data/settings/providers.json`。可用 `CTFBOT_SETTINGS_DIR` 改变此目录。文件以私有权限原子写入，不存密钥。CLI solve 也装载同一自定义端点配置，模型 ID 与 provider ID 可在文件中查看。普通 CLI 默认模型仍由其参数或 CTFBOT_PROVIDER/CTFBOT_MODEL 指定。Pi 凭据不保存在此目录。OAuth 登录所需的安装设备 ID 通过 Pi SettingsManager 从 Pi 全局 settings.json 获取或创建并持久化，不采用项目设置中的 deviceId；工作台与 Pi 共用同一安装身份。

## 导入、解题与查看结果

`/import <文件或 workspace 路径>` 打开已有 workspace，或询问题目目标并导入附件；路径含空格时直接填写，不需要额外加引号。附件传输授权在导入时明确选择。未授权的 workspace 可查看，运行需重新导入并授权。

`/image <本地镜像>` 更换工具镜像；`/network <grant.json>`、`/memory <snapshot.json>` 设置本次工作台会话的显式网络许可和受审记忆，`off` 关闭。网络和记忆配置不跨启动保存，格式见 [configuration.md](configuration.md)。工具镜像始终只从本机使用。

`/run` 展示题目、模型、API 地址和思考强度，确认后开始运行。运行前输入普通文字保存补充要求；运行中普通文字作为 steering 输入发送给 agent。`/stop` 中断当前运行并等待容器与后台进程清理。运行清理错误会展示，并保留原有恢复产物。

`/state` 查看概览，`/state assets`、`/state experiments` 查看产物和实验，`/state summaries latest` 查看最近公开摘要；`/flags` 查看全部候选；`/writeup` 阅读解题报告；`/report` 生成并阅读运行报告。文档用方向键/PgUp/PgDn 浏览，Enter/Esc 返回。候选提交不代表比赛平台验证通过。首次接入真实服务时，认证和实际模型请求仍需用户自己的账户、额度及网络环境。

## 模块边界

`src/ui/workbench-view.js` 负责 Pi TUI 组件、布局、输入和临时对话框；`src/ui/workbench.js` 协调用户命令与应用服务；`src/pi/catalog.js` 负责模型目录、Pi 认证委托及非敏感设置。工作台复用 `application/solve.js`，传入同一个 ModelRuntime；agent 循环、会话、重试和压缩仍由 Pi 提供。UI 不直接执行解题工具，也不启动完整 Pi CLI 的宿主工具。

## 登录故障提示

ChatGPT 登录必须向 Pi 传入 `getDeviceId`。工作台现使用 Pi 自身的全局设置管理器生成/复用 UUID，并在登录前确认保存成功；无需用户手工生成。此前缺少这个回调会在生成授权 URL 前直接失败。

常见故障会区分显示：Pi 设置无法保存、设备 ID 无效、1455 回调端口占用、回调 URL 不完整/状态不匹配、网络连接失败、令牌交换 HTTP 状态码及凭据同步失败。不会把服务响应正文、回调 code 或 token 显示在日志中。1455 被其他登录占用时，取消相应 Pi/Codex 登录再重试；不会自动终止其他进程。

解题日志按公开模型说明和工具卡片分块，不显示轮次标题。每次工具调用显示编号、用途、实际指令或关键参数、短代码预览；返回后在同一卡片更新状态、耗时、退出码、输出摘要和证据编号。stdout 与 stderr 分开，长命令输出保留尾部摘要；截断内容会明确标注，完整输出仍在运行证据中。候选提交与局部检查分别展示，不把工具返回成功解释为平台接受。

CLI `solve` 使用相同的工具说明与摘要，通过相同编号关联调用和返回。二进制数据和图片不展开为日志文本，工具卡片过滤终端控制序列并对常见凭据字段脱敏；模型服务返回的思考文本单独显示，签名和隐藏字段不显示。

## 右侧解题进展

侧栏沿用工作台的青色标题、灰色提示与分栏布局，独立滚动显示当前目标、正在进行的操作、当前方案、关键线索、待验证假设、下一步、阻塞与缺口、已有能力、更正、最近实验、文件与中间结果及运行结果。候选 Flag 保留原文，通过 `/flags` 查看全部。

模型调用 `summary_update` 更新公开摘要；摘要带更新时间，新的实际观察到来后标注“有新观察，以下为上次摘要”。操作状态实时更新。线索、假设和实验解释属于模型整理，不代表控制器已证明。模型在方向、关键证据、下一步或阻塞变化时更新摘要，简单任务不强制增加摘要步骤。

文件显示含义、大小和来源，例如“Base64 解码结果”“提取的 config.json”。脚本调用 `asset_capture` 时可选填 `display_name` 提供简短名称；该名称仅影响展示，不改变文件路径、哈希、血缘或工具引用。内部 ID 保留在 `/state` 与运行证据中。

状态栏耗时在一分钟内显示秒，之后显示 `分:秒`，一小时后显示 `时:分:秒`；token 数自动缩写为 K/M。上下文显示 Pi 当前上下文估算的百分比与 `当前长度/模型窗口大小`，例如 `上下文 25% (32K/128K)`，与整次会话累计 token 分开。尚未开始或压缩后等待新响应时显示“待更新”。

上下文按四层管理，每 10 个完成的解题轮次自动整理一次有变化的当前状态和核心参考；窗口阈值触发的压缩单独处理较早交互。自动整理结果也用于右侧摘要，`/state context_snapshots latest` 可查看其来源与版本。机制与失败处理见 [context-management.md](context-management.md)。

模型输出区分“模型思考（服务返回）”与“模型说明（公开）”，流式更新，并在最终消息到达时补齐 TUI 内容。工具供应的检查、下载、安装、验证与失败状态实时显示；右侧解题进展保留最新状态。思考文本只用于展示，不写入公开解题摘要或 `assistant_message` 证据；Pi 自身会话仍按 SDK 的规则保存。
