# 解题上下文管理

总结的核心 references 同时选择恢复目标；程序沿资产生成图计算 recovery_plan，和快照一起保存。停止时补入总结后生成的产物，不额外调用模型。完整机制见 [resume.md](resume.md)。

使用当前固定的 Pi SDK 1.1.0。Pi 保留 agent loop、工具调度、消息协议、压缩切点和窗口阈值检查；应用通过扩展提供结构化记忆，不另建 agent 框架。

## 四层结构

1. **静态系统与工具**：初始化时配置，后续保持稳定，模型请求仍携带这些内容。
2. **压缩历史**：累积的公开探索路线，以及压缩时的任务状态快照。由 Pi 的 CompactionEntry 保存，并标明状态版本。
3. **当前任务与关键参考**：原始题目、初始用户补充、最新任务状态、已提交候选的记录入口，以及核心附件/中间文件的名称、描述、哈希与血缘。每次请求从当前 RunState 生成一个视图，不追加进交互历史。
4. **近期原始交互**：用户消息、模型回复、工具调用和返回。原生 reasoning 协议由 Pi 保持；维护请求只读取公开文本、工具调用和结果，不提取隐藏推理。

窗口阈值针对整体上下文，压缩对象仅是较早的交互消息。静态层不参与摘要。旧压缩信息由新压缩结果替换；当前状态和参考索引独立更新。近期消息由 Pi 保留，不自行裁剪调用与返回关系。

原始任务持续保留。后续用户有效要求保存在近期交互和结构化状态/历史中；摘要与附件内容都不能变更应用层授权。

## 两类触发

**周期整理**：累计 10 个完成的解题模型轮次，在下次请求前启动后台整理，主会话继续解题。后台只产生待发布草稿，在后续请求的 context 钩子中采用，不在工具执行中途改变当前请求。轮次由 Pi 的 turn_end 事件计数，一次响应及其工具批次算一轮；失败、取消、截断响应，以及维护请求不计数。程序确定的新增文件、文件元数据和候选记录立即可见，不等待周期整理。模型仍可在关键变化时调用 summary_update、claim_record、experiment_record；下次请求立即反映新的公开摘要。

启动时同步固定上次状态、已有压缩历史、新增公开交互、RunState 副本、来源版本、覆盖轮次和文件/观察数量；引用校验与恢复路径计算也使用同一副本。期间新增的文件立即可见，较新的公开摘要按来源版本优先，迟到结果不能因为写入时间较晚而覆盖它。

整理输入为上次状态、已有压缩历史、新增公开交互及有界的 RunState 视图。输出只写当前状态快照和参考注释，不删交互，也不创建 Pi 压缩条目。主解题会话不递归发起 prompt；维护请求通过同一 ModelRuntime、同一选定服务与模型发起，无工具权限。

**窗口压缩**：Pi 根据模型窗口、保留量和输出预留自动触发 session_before_compact。输入为上次历史摘要和本次压缩范围内的公开交互，同时参考当前 RunState。重写完整探索路线，合并重复尝试，更新压缩时状态与当前参考。保留 firstKeptEntryId。Pi 确认压缩条目落盘后，应用提交关联的 RunState 快照。压缩开始时使旧后台任务失效并发送取消，不等待远端请求退出；压缩本身仍同步执行以保证窗口安全。压缩覆盖轮次计入整理水位。正常只有一个后台槽位，取消后也要等原请求实际结束才释放；若压缩抢占时服务未及时响应取消，短时可能同时存在退出中的旧请求与压缩请求。

总结回复仅接受完整 JSON 或完整包裹的 JSON 代码块，不从任意说明文本中猜测提取对象。当前 Pi SDK 的通用 completeSimple 没有统一 JSON Schema 输出参数，因此通过提示词提供 schema，并在本地严格校验。格式、字段、引用或输出长度错误允许一次修复请求；修复次数覆盖整次总结的所有历史批次，不按批次重复放大。所有维护调用（包括失败和修复）的用量均计入 Pi。

周期整理失败时保留旧快照和原始交互，按连续失败次数在后续 2、4、10 个完成模型轮次后重试，之后保持 10 轮间隔。同一轮重复投影不会触发重复重试；成功提交后按摘要实际覆盖轮次加 10 轮调度，不重置累计轮次。摘要覆盖第 10 轮、完成时已到第 35 轮，下次边界只补一次第 35 轮快照，不为第 20、30 轮分别排队，也不再等额外 10 轮。每次回复的公开文本及校验结果保存在 context_summary_response 证据中，不记录思考正文。压缩失败经有限修复仍不成功时，不回退到默认摘要器、不提交新压缩条目，停止运行并保留证据。用户停止和任务结束使旧任务代次失效并取消请求，禁止提交迟到结果；关闭只等待已接受的本地日志写入，不等待远端模型。后台失败不会污染主解题请求的认证/请求错误。

## 记录、预算与可追溯性

RunState 增加 context_snapshots。每个快照包含 schema_version、kind、source_revision（输入状态版本）、state_revision（实际持久化版本）、source_turn、source_time（取材时间）、generated_time（生成时间）、结构化记忆、公开摘要、覆盖的公开消息 ID、完整公开转录的证据引用、维护用量，以及关联的 Pi 压缩条目 ID。使用 `/state context_snapshots latest` 查看；过长结果通过现有 artifact_read 恢复。

结构化记忆保存 goal、user_constraints、facts、hypotheses、rejected_routes、unverified_attempts、approach、next_steps、blockers、corrections、achieved_capabilities、remaining_gap 和 references。结论标记 controller_proven=false。缺少观察/实验引用的排除结论保留为 unverified_attempts（失败尝试，未排除），不丢弃整份有效摘要；未知或编造引用仍拒绝并要求修复。被排除路线必须写清检查范围并引用实际观察/实验，文件描述不能替换文件元数据。引用校验后才提交；后台允许输入之后状态继续增长，且只能引用输入时已存在的记录。压缩仍要求状态版本不变。覆盖消息优先使用 Pi 公开会话条目 ID、条目内序号和公开内容哈希，区分重复的用户纠正；身份不明确时保守重读。

动态状态和参考预算随窗口调整，上限约 8K 估算 tokens；维护单次输入上限约 24K、输出不超过选定模型限制和 4K。原始题目和初始补充单独预留，不截断。近期保留量不超过约 20K。压缩阈值额外为动态注入与输出留空间。整体上下文统计、阈值判断及服务端超限后的压缩恢复统一由 Pi 负责；不对完整消息 JSON 做字节估算，图片 Base64 和 reasoning 签名不按普通文本计数。动态层保持有界，并通过压缩预留量为其留出空间。

历史较长时按原始顺序分批整理，每批继承前一批的路线，并按最新摘要大小重新计算输入容量，不跳过中间批次。小窗口下可缩减近期记录视图，完整 RunState 不变。单条巨型消息使用头尾摘要，并留下完整公开转录的证据引用；省略内容不作为否定判断的依据。完整文件、实验记录和 Pi 原始会话继续保存在外部。

周期整理和压缩的每次维护调用先独立保存 context_usage 收据，再在下次请求、压缩或关闭边界通过 Pi appendUsage 计入累计用量，避免后台追加 usage 改变活动会话叶子。尚未追加的收据实时计入状态栏，追加后不重复统计；无效结构和修复请求同样计入。关闭后才到达且未被接受的迟到服务响应不再写入会话，实际账单仍以服务端为准。状态栏在 Pi 的上下文统计上，使用 Pi estimateTokens 补偿当前动态文本注入的变化；已有 provider 用量包含的注入不重复相加，压缩后未知长度仍显示“待更新”。

右侧摘要优先展示较新的公开摘要或自动维护快照。TUI/CLI 明确打印整理开始、一次修复、更新成功或最终失败。右侧显示后台整理状态、摘要覆盖轮次、生成时间、失败原因及剩余重试轮数，并将无依据的失败尝试与排除结论区分展示，不新增解题轮次标题。

Skill 索引在初始化时常驻；正文和参考按需进入交互上下文，可被 Pi 压缩。动态状态保留近期 Skill 来源哈希；路线回顾复用每十轮总结，只整理实际尝试、测试范围、未解释输出与仍相关的已有提议，不生成新解法。旧复核仅保留历史记录入口，不作为待办或当前指令。完整记录可由 state_read 恢复。Resume 读取历史 Skill 快照，不依赖原始目录继续存在。详见 [skills.md](skills.md)。

## 证据优先与可替换计划

当前视图预算不足时先舍弃可替换计划和可恢复的展示内容，尽量保留关键事实、测试边界、未定问题和证据引用。测试条目按整体保留或省略，不能只留下排除结论而删掉 scope。预算极小时使用快照恢复入口；完整 RunState 不变。当前计划明确标为快照形成时的提议，后续证据可替代；resume 不盲目执行旧计划。

不新增实验门禁、独立评审请求或语义重复判定器。精确相同执行请求提供一次历史结果引用，明确文件内容、环境和随机性可能变化；不阻止执行，不判定路线无效。结构化 workflow 还可基于已确认的输入哈希和参数提示历史结果。

Pi 的收尾提示仅要求保存报告，最多补发一次；有依据的工作可继续，没有可执行的合理下一步时允许如实 run_complete(unsolved)。普通文本不会自动记成任务完成，重复忽略收尾协议按协议失败处理，不无限注入继续探索指令。

后台整理不阻塞主会话等待摘要，但仍共享所选服务的配额、连接和机器资源，服务端限流可能影响两类请求。窗口压缩不改为后台操作。
