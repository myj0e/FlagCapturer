# 解题上下文管理

使用当前固定的 Pi SDK 1.1.0。Pi 保留 agent loop、工具调度、消息协议、压缩切点和窗口阈值检查；应用通过扩展提供结构化记忆，不另建 agent 框架。

## 四层结构

1. **静态系统与工具**：初始化时配置，后续保持稳定，模型请求仍携带这些内容。
2. **压缩历史**：累积的公开探索路线，以及压缩时的任务状态快照。由 Pi 的 CompactionEntry 保存，并标明状态版本。
3. **当前任务与关键参考**：原始题目、初始用户补充、最新任务状态、已提交候选的记录入口，以及核心附件/中间文件的名称、描述、哈希与血缘。每次请求从当前 RunState 生成一个视图，不追加进交互历史。
4. **近期原始交互**：用户消息、模型回复、工具调用和返回。原生 reasoning 协议由 Pi 保持；维护请求只读取公开文本、工具调用和结果，不提取隐藏推理。

窗口阈值针对整体上下文，压缩对象仅是较早的交互消息。静态层不参与摘要。旧压缩信息由新压缩结果替换；当前状态和参考索引独立更新。近期消息由 Pi 保留，不自行裁剪调用与返回关系。

原始任务持续保留。后续用户有效要求保存在近期交互和结构化状态/历史中；摘要与附件内容都不能变更应用层授权。

## 两类触发

**周期整理**：累计 10 个完成的解题模型轮次，在下次请求前整理有变化的状态与参考。轮次由 Pi 的 turn_end 事件计数，一次响应及其工具批次算一轮；失败、取消、截断响应，以及维护请求不计数。程序确定的新增文件、文件元数据和候选记录立即可见，不等待周期整理。模型仍可在关键变化时调用 summary_update、claim_record、experiment_record；下次请求立即反映新的公开摘要。

整理输入为上次状态、已有压缩历史、新增公开交互及有界的 RunState 视图。输出只写当前状态快照和参考注释，不删交互，也不创建 Pi 压缩条目。主解题会话不递归发起 prompt；维护请求通过同一 ModelRuntime、同一选定服务与模型发起，无工具权限。

**窗口压缩**：Pi 根据模型窗口、保留量和输出预留自动触发 session_before_compact。输入为上次历史摘要和本次压缩范围内的公开交互，同时参考当前 RunState。重写完整探索路线，合并重复尝试，更新压缩时状态与当前参考。保留 firstKeptEntryId。Pi 确认压缩条目落盘后，应用提交关联的 RunState 快照。压缩同时满足待执行的周期整理，不重复请求。

周期整理失败时保留旧快照和原始交互，通知用户，并在后续 10 轮后重试。压缩失败不回退到默认摘要器，不提交新压缩条目，停止本次运行并保留证据。用户停止会取消维护请求，禁止提交取消后的结果。任务已经结束时不再发起周期整理。

## 记录、预算与可追溯性

RunState 增加 context_snapshots。每个快照包含 schema_version、kind、source_revision、state_revision、结构化记忆、公开摘要、覆盖的公开消息 ID、完整公开转录的证据引用、维护用量，以及关联的 Pi 压缩条目 ID。使用 `/state context_snapshots latest` 查看；过长结果通过现有 artifact_read 恢复。

结构化记忆保存 goal、user_constraints、facts、hypotheses、rejected_routes、approach、next_steps、blockers、corrections、achieved_capabilities、remaining_gap 和 references。结论标记 controller_proven=false。被排除的路线必须写清检查范围并引用实际观察/实验，文件描述不能替换文件元数据。引用校验后才提交；状态版本发生变化则丢弃过期结果。

动态状态和参考预算随窗口调整，上限约 8K 估算 tokens；维护单次输入上限约 24K、输出不超过选定模型限制和 4K。原始题目和初始补充单独预留，不截断。近期保留量不超过约 20K。压缩阈值额外为动态注入与输出留空间。整体上下文统计、阈值判断及服务端超限后的压缩恢复统一由 Pi 负责；不对完整消息 JSON 做字节估算，图片 Base64 和 reasoning 签名不按普通文本计数。动态层保持有界，并通过压缩预留量为其留出空间。

历史较长时按原始顺序分批整理，每批继承前一批的路线，并按最新摘要大小重新计算输入容量，不跳过中间批次。小窗口下可缩减近期记录视图，完整 RunState 不变。单条巨型消息使用头尾摘要，并留下完整公开转录的证据引用；省略内容不作为否定判断的依据。完整文件、实验记录和 Pi 原始会话继续保存在外部。

周期整理和压缩的每次维护调用均通过 Pi appendUsage 计入累计用量，包括返回了无效结构的请求，不重复计费统计。状态栏在 Pi 的上下文统计上，使用 Pi estimateTokens 补偿当前动态文本注入的变化；已有 provider 用量包含的注入不重复相加，压缩后未知长度仍显示“待更新”。

右侧解题摘要优先展示较新的模型公开摘要或自动维护快照。TUI 沿用现有风格，维护期间在右侧显示正在整理；失败会给出提示，不新增轮次标题。
