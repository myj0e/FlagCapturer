# 全局检查与修改记录（2026-10-11）

检查范围：Pi 会话与上下文、CLI/TUI 输出、工具注册与供应、Docker 生命周期、文件/产物流转、RunState/证据、恢复与回放，以及仓库交付。保持现有 Pi SDK 1.1.0 和当前 Docker image ID，不引入另一套 agent 循环。

## 已处理的问题

| 问题 | 影响 | 设计与修改 |
|---|---|---|
| 缺少依赖只能人工改镜像 | 中断解题，可能重复下载大型工具 | 控制器供应固定配方，优先复用现有镜像；小型 wheel 在独立无网络容器安装为只读扩展 |
| 临时容器和主沙箱各有 tmpfs | 直接切换容器会丢工作文件或交互状态 | 主沙箱保留；扩展执行显式传递资产/脚本，输出导回证据和 RunState；不隐式共享 `/work` |
| 依赖安装成功不代表组合可用 | Python 库与本地程序仍可能不兼容 | 配方组合验证实际 import、最小功能、命令及 pip check；验证后原子发布缓存 |
| 缓存可能损坏、标签可漂移 | 使用错误或变化的工具环境 | 固定 image ID，缓存键包含配方和锁文件；复用和执行前校验完整清单，拒绝符号链接及特殊文件 |
| 背景准备与前台工具并发写状态 | 同一 section 可能分配重复 ID | RunState 统一串行持久化，保持 ID、状态与证据顺序一致 |
| 供应容器中断后缺少恢复记录 | 遗留资源无法确认归属 | 创建前保存活动容器回执，确认清理后移除；recover 验证 run label 后处理工具容器 |
| 失败/取消容易触发重复安装 | 重复下载、误把半成品当作可用 | 失败请求本运行内保留，取消等待清理；只有通过完整验证才能 ready |
| 回放未识别扩展执行 | 可能跳过关键操作却报告回放成功 | 映射环境、脚本、输入与输出 ID；扩展仅用已校验缓存，缺失时明确失败，不在回放中下载 |
| CLI/TUI 只消费 text_delta | 服务返回的思考文本被忽略 | 思考与说明分区展示；按 contentIndex 去重，TUI 最终消息补全；签名/不透明字段不进入展示 |
| 16 MiB 产物导出受较小 Base64 上限限制 | 超过约 1.5 MiB 的合法产物导出失败 | 以声明的导出上限计算 Base64 边界；使用线性字符/填充校验，避免长重复正则的栈问题 |
| 运行时参数缺少直接边界校验 | 应用层直接调用可能传入无效时限/输出上限 | DockerRuntime 统一校验执行时限与输出限制 |
| 输出文件导出失败会掩盖执行日志 | 无法判断实际命令是否成功 | 扩展命令完成后先保存退出状态、stdout/stderr、输入哈希，再处理输出资产 |
| 本地没有 Git 元数据 | 当前重构无法审阅或交付 | 恢复现有远端历史后提交当前版本；忽略运行数据、缓存、Python 字节码和私钥文件 |

供应能力同步进入 TUI 右栏及压缩后的动态上下文；工具执行可以作为 experiment_record 的执行观察，继续使用既有来源与产物机制。思考展示不改变公开摘要的语义，也不把服务未返回的隐藏内容变成文本。

## 维持的边界

自动供应目前有明确目录，不能安装任意包、原生源码或未知大型工具。当前镜像内已有重型工具无需重新下载。扩展只读且不注入主沙箱，用户脚本需要通过 tool_exec 选择环境。GUI、设备、许可证、题目网络授权仍各自独立；这些条件不会通过安装接口隐式获得。

没有对所有第三方工具功能、所有模型服务或所有真实题目作全面正确性承诺。最终验收使用合成 provider/附件与真实 Docker，不调用收费模型，不运行原有大型工具的重复冒烟检查。
