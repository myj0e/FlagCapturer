# Skills 与上游知识库

FlagCapturer 使用 Pi SDK 1.1.0 的 Skill 解析、资源目录与 `/skill:name` 展开。系统上下文只包含名称、描述和入口，正文及参考按需读取。模型自动选用指南，也可以显式指定。

```text
/skills
/skill:ctf-forensics 检查文件结构及尚未解释的尾随内容
/skill:ctf-route-review 重新检查当前路线的前提
```

空闲时显式选择作用于下一次 `/run`；运行时通过 Pi steering 排队，在当前轮次结束后送入模型。普通补充文字同样区分已排队与已送达。读取指南不等于已经完成其中的操作。

CLI 使用 `--skill ctf-forensics` 选择入口，`--skill-path /absolute/skills-directory` 添加目录（可重复）。项目内置目录是 `assets/skills`，用户默认目录是 `~/.config/flagcapturer/skills`。不扫描题目目录、宿主 `.agents/skills` 或 Pi 全局包。名字冲突遵循 Pi 的首次发现优先规则，并公开诊断；内置名称优先。

## 来源及适配

上游：<https://github.com/ljagiello/ctf-skills>，固定 commit `c332c7be1b27cb64639a20124ac55ba916adef92`，MIT。原始许可证与 132 个原始文件保存在 `assets/vendor/ctf-skills`；`SOURCE.json` 记录逐文件 SHA-256。包括九类技术指南、调度与报告指南，以及六个小型脚本，总计约 2.8 MB。没有引入完整 Git 历史、上游安装器、工具依赖或 PayloadsAllTheThings。

`assets/skills` 是独立维护的十二个入口：十一项上游适配与一个路线复核指南。上游正文保持原始字节；适配入口解释当前可执行工具、依赖供应、路径、权限和完成条件，并直接链接分类参考。原文中安装器和贡献指南链接属于上游仓库资源，不是本地执行入口。

对全部引入文件按以下环境冲突分类处理，不通过批量文本替换改变技术示例：

| 上游假设 | 当前执行方式 |
|---|---|
| Bash、Read、Write、Edit、Skill 等宿主工具 | 沙箱工具及受控 `skill_read`；不开放宿主执行 |
| pip/apt/brew、下载项目或 payload 库 | 先检查现有能力，再按已有目录使用 `tool_request`；不自动安装 |
| 磁盘挂载、特权设备与内核能力 | 优先用户态提取；不支持的前提公开报告 |
| curl、requests、pwntools 直接联网 | 当前授权与注册网络工具决定能力；指南不增加授权 |
| 平台 API token、平台提交、全库唯一性检查 | 仅在用户明确请求且能力可用时执行；沿用现有候选与完成机制 |
| 示例固定路径与工具版本 | 在沙箱中核对实际路径、版本、输入和算法条件后使用 |

示例代码是参考模板，不代表已经验证其适用于当前题目。上游知识不替代 RunState 中的实际观察，也不构成新的权限。

## 资源读取与脚本

- `skill_list` 列出指南和加载诊断。
- `skill_read(name=...)` 读取入口；`path` 支持登记的资源 key、广告中的绝对路径，或相对指定 Skill 的路径。参考之间的链接按返回的 `reference_base` 解析。
- 大文件使用 `offset` 与 `next_offset` 按字符分页；JSON 编码后的正文有独立大小限制，避免工具返回再次截断。只读取有用章节，不将整库塞入上下文。
- `skill_materialize(path=...)` 将登记的小型脚本复制为证据资产，返回 `/work` 路径。它不执行脚本；后续执行仍经过普通沙箱工具，并声明输入、输出及依赖。

每次运行将登记的文本资源保存为内容寻址证据和只读文件快照。读取工具使用已保存并校验哈希的字节，拒绝未登记路径与符号链接。目录限 1,000 个文件、总计 8 MiB、单文件 1 MiB，不自动加载二进制资产。

## 上下文、路线复核与恢复

`skill_catalogs` 保存目录、文件哈希与快照；`skill_uses` 保存按需读取、显式调用和脚本准备。动态上下文与周期总结保留近期采用的指南及路线决定；正文仍可压缩，不作为不可压缩的常驻内容。

路线复核并入现有每十轮状态整理，不再按十二次执行或候选/claim 数量触发，也不要求读取指南或填写复核记录。维护模型只归纳已有尝试、观察、测试范围和未解释问题；下一实验由主 agent 选择。`ctf-route-review` 仍可按需使用。历史 `route_reviews` 与 `route_review_record` 保留读取/补记兼容；旧建议不作为当前指令常驻。

图像取证入口新增 `image-interleaving.md` 与 `space-filling-curves.md`，对应可检索方法卡片。光栅 helper 使用现有 Pillow，按有限行列周期和相位输出带参数拼图、源哈希及覆盖清单；不执行 OCR、不排名，也不预设下一步使用 Peano。用 `skill_materialize` 准备脚本后通过沙箱执行，保存重要拼图和 manifest。

Resume 使用历史记录的完整 Skill 快照，支持历史绝对路径映射；即使原自定义目录已经删除或修改，也能读取原版本。新运行才使用更新后的源文件。方法卡目录仍由应用版本提供；如果新卡片引用的辅助资源不在旧快照中，按卡片中的直接算法说明使用已有沙箱能力，或在新任务中获取新脚本，不反复请求缺失资源。已有旧记录没有 Skill 快照时会建立当前目录快照，不改变历史证据。

维护上游更新时应固定新 commit，重新核对许可证、资源引用与环境冲突，更新逐文件哈希，运行最终验收；不在解题期间自动更新。

每十轮的路线整理随任务摘要在后台执行，不另起评审 agent。输入与 Skill 来源在启动时固定，下一次请求采用通过校验的摘要；新用户要求和后续证据优先于旧计划。
